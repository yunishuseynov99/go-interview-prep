# A Framework for System Design Interviews: конспект

## Зачем нужно это интервью

- Симуляция реальной работы: два коллеги совместно решают **ambiguous** задачу. Идеального ответа нет.
- Процесс важнее финального дизайна. Показываешь, как ты проектируешь, защищаешь решения и реагируешь на feedback.
- Что оценивает интервьюер: technical design, **collaboration**, работа под давлением, умение **resolve ambiguity**, умение задавать хорошие вопросы.
- **Red flags**: over-engineering (игнорирование tradeoffs), narrow mindedness, stubbornness.

## 4-step framework

### Step 1. Understand the problem и establish design scope (3-10 мин)

- **Не будь «Jimmy»**: нельзя сразу выдавать ответ. Быстрый ответ без понимания требований это red flag, а не плюс.
- Задавай вопросы про требования и assumptions. Если интервьюер не отвечает, говорит делать assumptions: **записывай их** на доску.
- Что спросить:
  - Какие конкретные features строим?
  - Сколько пользователей?
  - Как быстро растём (3 месяца, 6 месяцев, год)?
  - Какой tech stack, какие существующие сервисы можно использовать?
- Пример для news feed: mobile/web/both? Главные features (post + видеть feed друзей)? Порядок (reverse chronological или ranked)? Сколько друзей (5000)? Трафик (10M DAU)? Есть ли media (images, video)?

### Step 2. High-level design и get buy-in (10-15 мин)

- Делаем initial blueprint, **просим feedback**, относимся к интервьюеру как к teammate.
- Рисуем box diagrams: clients (mobile/web), APIs, web servers, data stores, cache, CDN, message queue.
- Делаем **back-of-the-envelope** оценку, чтобы проверить, что дизайн вписывается в scale. Сначала спроси, нужна ли она.
- Проходим по нескольким **concrete use cases**: помогает найти edge cases.
- API endpoints и DB schema: зависит от задачи. Для «Design Google Search» это слишком low level, для backend multiplayer poker нормально. Уточняй у интервьюера.
- Пример news feed: два flow: **feed publishing** (пост пишется в cache/DB и раскладывается в feed друзей) и **news feed building** (агрегация постов друзей в reverse chronological order).

### Step 3. Design deep dive (10-25 мин)

- К этому моменту: согласованы goals и scope, есть high-level blueprint, есть feedback, понятно, куда копать.
- Вместе с интервьюером **приоритизируй компоненты**. Сначала самые критичные.
- Куда может пойти интервью:
  - Упор на high-level design.
  - Для senior: performance characteristics, **bottlenecks**, resource estimations.
  - Детали отдельных компонентов. Примеры: URL shortener (hash function для длинный → короткий URL), chat system (снижение latency, online/offline status).
- **Time management**: не увязай в мелочах, которые не показывают навык. Пример: EdgeRank в деталях это трата времени, она не доказывает умение проектировать scalable system.

### Step 4. Wrap up (3-5 мин)

- **Bottlenecks и улучшения**: никогда не говори «мой дизайн идеален».
- Короткий **recap** дизайна, особенно если предлагал несколько вариантов.
- **Error cases**: server failure, network loss.
- **Operations**: monitoring метрик и error logs, как делать rollout.
- **Next scale curve**: что менять, чтобы с 1M юзеров дойти до 10M.
- Какие refinements сделал бы, будь больше времени.

## Dos

- Всегда уточняй, не считай свои assumptions верными.
- Пойми требования: нет «правильного» ответа, дизайн для стартапа и для компании с миллионами юзеров отличается.
- **Думай вслух**, коммуницируй.
- Предлагай несколько подходов.
- После согласования blueprint углубляйся в компоненты, начиная с самых критичных.
- Bounce ideas с интервьюером.
- Не сдавайся.

## Don'ts

- Не иди неподготовленным к типичным вопросам.
- Не прыгай в решение без требований и assumptions.
- Не уходи в детали одного компонента в начале: сначала high-level, потом drill down.
- Если застрял, проси hint.
- Не думай молча.
- Интервью не закончено, пока интервьюер не скажет. Проси feedback рано и часто.

## Time allocation (45 минут)

| Step | Время |
|---|---|
| 1. Understand problem + scope | 3-10 мин |
| 2. High-level design + buy-in | 10-15 мин |
| 3. Deep dive | 10-25 мин |
| 4. Wrap up | 3-5 мин |

## Шпаргалка: что сказать в начале интервью

1. «Давайте уточню требования»: features, scale (DAU), рост, tech stack.
2. Записываю assumptions.
3. Рисую high-level, прошу feedback.
4. Оцениваю QPS/storage, если уместно.
5. Предлагаю, что углубить, и согласовываю с вами.
6. В конце: bottlenecks, failure cases, monitoring, следующий scale.
