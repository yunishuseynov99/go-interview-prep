Отличный вопрос. **Context** — это, пожалуй, один из самых важных пакетов в Go, потому что это стандартный способ управления жизненным циклом запроса, проходящего через границы API и процессов.

Вот как я бы ответил на собеседовании, структурируя ответ от определения к деталям и лучшим практикам:

---

# Мой ответ на собеседовании: «Расскажи про Context»

**Context** — это интерфейс, который предназначен для решения трёх основных задач в конкурентных программах:
1.  **Отмена операций (Cancellation):** Сигнал о том, что работу нужно прекратить (например, клиент закрыл соединение).
2.  **Управление временем (Deadlines/Timeouts):** Ограничение времени выполнения операции.
3.  **Передача данных (Request-scoped values):** Хранение метаданных (trace ID, user ID) в рамках одного запроса.

---

### Как это устроено внутри

Контекст работает как **дерево**.
У нас есть корневой контекст (обычно `context.Background()`), и мы создаем от него дочерние контексты с помощью функций `WithCancel`, `WithTimeout`, `WithValue`.

Главное правило: **Если отменяется родительский контекст, каскадно отменяются и все его дети.** Это гарантирует, что у нас не останется "повисших" горутин, которые продолжают молотить процессор, когда результат уже никому не нужен.

Сам интерфейс `Context` выглядит просто:
- **`Done() <-chan struct{}`**: Возвращает канал, который закрывается при отмене. Это сигнал для остановки работы.
- **`Err() error`**: Говорит, почему контекст закрылся (`Canceled` или `DeadlineExceeded`).
- **`Deadline()`**: Возвращает время дедлайна, если оно есть.
- **`Value(key any) any`**: Позволяет достать значение по ключу.

---

### Основные паттерны использования

**1. Отмена и Таймауты (наиболее частый кейс)**
Мы используем контекст, чтобы не блокировать горутины навечно. Например, при походе в базу данных или внешний API:

```go
// Создаем контекст, который "умрет" через 100 мс
ctx, cancel := context.WithTimeout(parentCtx, 100*time.Millisecond)
defer cancel() // Обязательно вызываем cancel для очистки ресурсов!

req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
// Если сервер не ответит за 100мс, Do вернет ошибку context.DeadlineExceeded
res, err := client.Do(req)
```

**2. Обработка отмены в своей горутине**
Если я пишу воркер, я обязан слушать канал `ctx.Done()`:

```go
func longRunningTask(ctx context.Context) {
    for {
        select {
        case <-ctx.Done():
            // Нас попросили выйти (или истек таймаут)
            return 
        default:
            // Делаем полезную работу
        }
    }
}
```

**3. Передача данных (Values)**
`WithValue` используется для данных, которые *не влияют* на бизнес-логику, но нужны инфраструктуре. Примеры: RequestID, Logger, данные аутентификации.
*Важно:* Ключи для `WithValue` должны быть **неэкспортируемыми типами**, чтобы избежать коллизий между пакетами.

---

### Важные нюансы (Best Practices)

На интервью я всегда стараюсь упомянуть эти пункты, чтобы показать опыт:

1.  **`defer cancel()` обязателен.**
    Даже если операция завершилась успешно, нужно вызвать `cancel()`. Если этого не сделать в случае с `WithTimeout` или `WithCancel`, внутренний таймер и структуры контекста останутся в памяти до завершения *родительского* контекста. Это классическая утечка памяти (goroutine leak).

2.  **Context — первый аргумент.**
    По конвенции Go, контекст всегда передается первым аргументом функции: `func DoSomething(ctx context.Context, arg string)`.

3.  **Не хранить Context в структурах.**
    Контекст должен проходить сквозь стек вызовов, а не храниться как поле структуры (за редким исключением, вроде `http.Request`).

4.  **`Background` vs `TODO`.**
    - `context.Background()` — корень всего (main, init, тесты).
    - `context.TODO()` — "заглушка", когда не знаешь, какой контекст использовать, или планируешь добавить его позже. Технически они одинаковы, но семантически разные.

5.  **`WithValue` — не для параметров функции.**
    Это частая ошибка новичков. Нельзя передавать через контекст обязательные параметры (например, `dbConnection` или `userID` для бизнес-логики). Это делает код неявным и "хрупким", лишая нас типизации.

---

### Резюме

> **Context — это "кровеносная система" конкурентного кода в Go.** Он позволяет нам элегантно завершать целые деревья горутин, контролировать время выполнения запросов и безопасно пробрасывать метаданные трассировки. Без него написание надежных сетевых сервисов в Go практически невозможно.
