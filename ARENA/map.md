# Мой ответ на собеседовании: «Расскажи про map»

---

**Map** — это встроенный тип данных в Go, представляющий собой неупорядоченную коллекцию пар «ключ-значение», по сути — хеш-таблицу.

---

**По внутреннему устройству** — это указатель на структуру `runtime.hmap`. Именно поэтому map ведёт себя как ссылочный тип: при передаче в функцию копируется указатель, а не данные, и изменения видны снаружи.

Внутри — массив **бакетов**, каждый хранит до 8 пар. При поиске хеш ключа разбивается на две части: младшие биты определяют бакет, старшие 8 бит (tophash) — быстро сравниваются внутри бакета, и только при совпадении идёт полное сравнение ключа. Это даёт **амортизированный O(1)**.

---

**Основные моменты, которые важно знать:**

**Первое** — нулевое значение map это `nil`. Из `nil` map можно читать (вернётся zero value), но запись вызовет panic. Поэтому всегда нужен `make` или литерал.

**Второе** — ключом может быть только **comparable** тип. Слайсы, другие map, функции — нельзя.

**Третье** — порядок итерации **рандомизирован** намеренно. На него нельзя полагаться.

**Четвёртое** — map **не потокобезопасна**. Конкурентные чтение и запись — это не data race в классическом смысле, а **fatal error**, runtime это детектит. Решения — `sync.Mutex`, `sync.RWMutex`, или `sync.Map` для сценариев с редкой записью и частым чтением.

**Пятое** — нельзя брать адрес элемента (`&m[key]` — ошибка компиляции), потому что при росте map элементы могут переместиться в памяти.

**Шестое** — рост происходит при превышении load factor 6.5 (удвоение бакетов) или при большом количестве overflow-бакетов (перебалансировка без удвоения). Рост **инкрементальный** — эвакуация старых бакетов происходит постепенно, при каждой операции записи.

---

**Ну и comma-ok идиома** — `v, ok := m[key]` — позволяет отличить отсутствие ключа от хранимого zero value.
