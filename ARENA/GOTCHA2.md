### 11. Defer и именованные возвращаемые значения

**Вопрос:** Что вернет эта функция?

```go
func test() (result int) {
    defer func() {
        result++
    }()
    return 1
}

func main() {
    fmt.Println(test())
}
```

**Ответ:** `2`

**Почему:** В Go `defer` с анонимной функцией имеет доступ к именованным возвращаемым значениям.
Инструкция `return 1` делает следующее:
1. Присваивает `result = 1`.
2. Выполняет `defer` (где `result` увеличивается на 1, становясь 2).
3. Возвращает текущее значение `result`.

### 12. Длина строки (Bytes vs Runes)

**Вопрос:** Что выведет этот код?

```go
func main() {
    s := "Привет"
    fmt.Println(len(s))
    fmt.Println(utf8.RuneCountInString(s))
}
```

**Ответ:** `12` и `6`

**Почему:** В Go `string` — это slice байт, доступный только для чтения. Функция `len()` возвращает количество **байт**, а не символов.
Кириллические символы в UTF-8 занимают 2 байта.
`"Привет"` = 6 букв * 2 байта = 12 байт.
Чтобы посчитать количество символов (рун), нужно использовать `utf8.RuneCountInString`.

### 13. Утечка памяти в Slice (Slicing)

**Вопрос:** В чем проблема следующего кода, если `loadHugeFile` возвращает массив на 100 МБ?

```go
var stored []byte

func process() {
    hugeData := loadHugeFile() // []byte len=100MB
    stored = hugeData[:10]
}

func main() {
    process()
    // GC работает здесь...
}
```

**Ответ:** Весь массив на 100 МБ останется в памяти.

**Почему:** Слайс `stored` указывает на тот же базовый массив, что и `hugeData`. Несмотря на то, что мы используем только 10 байт, сборщик мусора (GC) не может освободить весь массив `hugeData`, так как на его часть все еще есть ссылка.
**Решение:** Нужно использовать `copy` или `strings.Clone` (для строк), чтобы скопировать нужные данные в новый, маленький массив.

### 14. Копирование sync.WaitGroup

**Вопрос:** Что произойдет при выполнении?

```go
func worker(wg sync.WaitGroup) {
    defer wg.Done()
    // work...
}

func main() {
    var wg sync.WaitGroup
    wg.Add(1)
    go worker(wg)
    wg.Wait()
}
```

**Ответ:** Deadlock (в `main`).

**Почему:** `sync.WaitGroup` (как и `sync.Mutex`) — это структура. При передаче в функцию она **копируется**. Горутина `worker` вызывает `Done()` на своей копии, а `wg` в `main` остается с счетчиком 1 и вечно ждет обнуления.
Примитивы синхронизации всегда нужно передавать по указателю.

### 15. Сравнение структур (Struct Comparability)

**Вопрос:** Скомпилируется ли этот код?

```go
type Data struct {
    ID   int
    Tags []string
}

func main() {
    d1 := Data{ID: 1, Tags: []string{"a"}}
    d2 := Data{ID: 1, Tags: []string{"a"}}
    
    if d1 == d2 {
        fmt.Println("Equal")
    }
}
```

**Ответ:** Ошибка компиляции: `struct containing []string cannot be compared`.

**Почему:** Структуры в Go можно сравнивать оператором `==` только если **все** их поля сравнимы. Слайсы (slices), карты (maps) и функции не поддерживают сравнение через `==`. Поэтому и структура, содержащая их, становится несравнимой.
Для сравнения нужно использовать `reflect.DeepEqual` (медленно) или писать свою функцию сравнения.

### 16. Variable Shadowing (Затенение переменных)

**Вопрос:** Что выведет код?

```go
func main() {
    x := 10
    if x > 5 {
        x, y := 5, 20
        fmt.Println(x, y)
    }
    fmt.Println(x)
}
```

**Ответ:** `5 20` затем `10`.

**Почему:** Оператор `:=` внутри блока `if` создает **новую** переменную `x`, которая "затеняет" внешнюю `x` только внутри этого блока (потому что используется `y`, который новый, и `:=` срабатывает). Внешняя переменная `x` не меняется. Это частая ошибка при обработке `err` (`res, err := func()`).

### 17. Recover и паники в других горутинах

**Вопрос:** Сработает ли `recover` в `main`?

```go
func main() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Recovered:", r)
        }
    }()

    go func() {
        panic("Ouch!")
    }()

    time.Sleep(time.Second)
}
```

**Ответ:** Нет, программа упадет (crash).

**Почему:** `recover` может перехватить панику только внутри **той же** горутины, где она произошла. Паника, возникшая в запущенной горутине, должна быть обработана внутри этой же горутины, иначе она "убивает" все приложение.

### 18. Copy и длина Destination

**Вопрос:** Что будет в `dst`?

```go
func main() {
    src := []int{1, 2, 3}
    var dst []int
    copy(dst, src)
    fmt.Println(dst)
}
```

**Ответ:** `[]` (пустой слайс).

**Почему:** Функция `copy(dst, src)` копирует `min(len(dst), len(src))` элементов. Поскольку `dst` инициализирован как `nil` (или просто пустой), его `len` равен 0. Ничего скопировано не будет.
Нужно делать `dst := make([]int, len(src))`.

### 19. Методы у nil-receiver

**Вопрос:** Упадет ли этот код с паникой?

```go
type Config struct {
    Port int
}

func (c *Config) String() string {
    if c == nil {
        return "<nil>"
    }
    return fmt.Sprintf("Port: %d", c.Port)
}

func main() {
    var c *Config // nil
    fmt.Println(c.String())
}
```

**Ответ:** Не упадет, выведет `<nil>`.

**Почему:** В Go вызов метода на `nil` указателе абсолютно легален, если сам метод внутри проверяет ресивер на `nil` и не пытается разыменовать его поля (например, не обращается к `c.Port` до проверки). Это отличает Go от многих языков (например, Java, где это вызвало бы NPE сразу при вызове).

### 20. Fallthrough в Switch

**Вопрос:** Что выведет код?

```go
func main() {
    i := 0
    switch i {
    case 0:
        fmt.Println("Zero")
    case 1:
        fmt.Println("One")
    }
}
```

**Ответ:** Только `Zero`.

**Почему:** Это "анти-gotcha" для пришедших из C/C++/Java/JS. В Go в конструкции `switch` **нет автоматического проваливания** (fallthrough) в следующий кейс. `break` не нужен. Если вам нужно провалиться дальше, нужно явно написать ключевое слово `fallthrough`.
