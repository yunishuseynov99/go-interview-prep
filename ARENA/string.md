# Мой ответ на собеседовании: «Что такое string в Go?»

**String в Go** — это **неизменяемый (immutable)** слайс байт.

Это значит, что строка — это не массив символов (как в C) и не объект (как в Java). Это структура данных, которая по умолчанию хранит текст в кодировке **UTF-8**.

### 1. Как это устроено внутри (String Header)

Под капотом строка — это маленькая структура (StringHeader), которая занимает всего **16 байт** (на 64-битной системе):

```go
type StringHeader struct {
    Data uintptr // Указатель на массив байт (backing array)
    Len  int     // Длина строки в байтах
}
```

**Важные следствия этого устройства:**
1.  **Дешевая передача:** Когда мы передаем строку в функцию, копируется только этот заголовок (16 байт). Сами данные не копируются.
2.  **Slicing (Срезы):** Операция взятия подстроки `s[1:5]` — это O(1). Мы просто создаем новый заголовок, который указывает на ту же область памяти, но со смещением. Память не дублируется.

---

### 2. Неизменяемость (Immutability)

Строки в Go нельзя менять.
```go
s := "hello"
s[0] = 'H' // Ошибка компиляции!
```

**Почему так сделано?**
*   **Безопасность при конкурентности:** Строки можно читать из тысяч горутин без блокировок, так как никто не может их изменить.
*   **Ключи мапы:** Так как хеш строки не меняется, её можно безопасно использовать как ключ в `map`.
*   **Оптимизация памяти:** Компилятор может дедуплицировать одинаковые строковые литералы.

---

### 3. Кодировка и Руны (Runes)

Это главный "подводный камень". Поскольку Go использует UTF-8:
*   **`len(s)` возвращает количество БАЙТ, а не символов.**
*   Если строка содержит кириллицу или эмодзи, один символ может занимать 2, 3 или 4 байта.

Чтобы работать с "символами", в Go есть тип **`rune`** (это алиас для `int32`).

**Как правильно итерироваться:**
```go
str := "Привет"

// 1. Побайтово (плохо для unicode)
for i := 0; i < len(str); i++ {
    fmt.Printf("%x ", str[i]) // Выведет байты
}

// 2. По рунам (правильно)
for i, r := range str {
    // i - индекс начала байта, r - сама руна (символ)
    fmt.Printf("%c ", r) 
}
```
Цикл `range` автоматически декодирует UTF-8 на лету.

---

### 4. Производительность (Concatenation)

Так как строки неизменяемы, любая конкатенация через `+` создает **новую** строку и выделяет новую память.

*   Для простых случаев (`a + b`) это нормально.
*   В циклах это убийство производительности (O(N^2) по аллокациям).

**Best Practice:**
Использовать **`strings.Builder`**.
```go
var sb strings.Builder
sb.Grow(100) // Опционально: преаллокация памяти (как cap у слайса)
for i := 0; i < 1000; i++ {
    sb.WriteString("text")
}
s := sb.String()
```
`Builder` работает напрямую с буфером байт и при вызове `String()` не копирует память, а использует `unsafe`, чтобы превратить байты в строку (zero-copy conversion).

---

### 5. Конвертация []byte <-> string

Обычно `string([]byte)` и `[]byte(string)` приводят к **копированию памяти** (аллокации), потому что байты мутабельны, а строка — нет.

Однако есть оптимизации:
1.  **Map Lookup:** `m[string(byteSlice)]` — компилятор не будет аллоцировать строку, он просто поищет хеш байт-слайса.
2.  **Unsafe (опасно):** Можно использовать `unsafe.Pointer`, чтобы привести `[]byte` к `string` без копирования, если вы гарантируете, что байты не будут меняться.

---

### Резюме

> **String в Go** — это неизменяемая структура (указатель + длина), оптимизированная под UTF-8.
> Она дешевая при передаче и создании подстрок.
> Главное помнить: `len()` — это байты, для символов нужны `rune`, а для конкатенации в цикле — `strings.Builder`.
