Вот подборка из 10 каверзных (gotcha) вопросов по Go, которые часто встречаются на собеседованиях, так как они затрагивают внутреннее устройство языка.

---

### 1. Замыкания в циклах (Loop Variable Capture)

**Вопрос:** Что выведет этот код? (Учитывая версии Go до 1.22 и после).

```go
func main() {
    var wg sync.WaitGroup
    values := []string{"a", "b", "c"}
    for _, v := range values {
        wg.Add(1)
        go func() {
            fmt.Println(v)
            wg.Done()
        }()
    }
    wg.Wait()
}
```

**Ответ:**
*   **До Go 1.22:** Скорее всего выведет `c`, `c`, `c` (порядок может меняться, но значения будут одинаковыми — последним элементом).
*   **С Go 1.22:** Выведет `a`, `b`, `c` (в произвольном порядке).

**Почему:** В старых версиях Go переменная цикла `v` переиспользовалась на каждой итерации. Горутина захватывала ссылку на одну и ту же переменную. К моменту запуска горутин цикл уже заканчивался, и `v` была равна "c".
В Go 1.22 это поведение изменили, и теперь переменная цикла создается заново для каждой итерации.

### 2. Nil Interface vs Typed Nil

**Вопрос:** Что выведет следующий код?

```go
func Foo() error {
    var err *os.PathError = nil
    return err
}

func main() {
    err := Foo()
    fmt.Println(err == nil)
}
```

**Ответ:** `false`

**Почему:** В Go интерфейс — это структура из двух полей: `(type, value)`. Интерфейс равен `nil` только тогда, когда **оба** поля равны `nil`.
В данном случае `err` (интерфейс `error`) содержит:
*   Type: `*os.PathError`
*   Value: `nil`
Поскольку тип присутствует, сам интерфейс не является `nil`. Это называется "Typed Nil".

### 3. Defer и вычисление аргументов

**Вопрос:** Что выведет этот код?

```go
func main() {
    i := 0
    defer fmt.Println(i)
    i++
    return
}
```

**Ответ:** `0`

**Почему:** Аргументы отложенной функции (`defer`) вычисляются **в момент объявления** defer, а не в момент вызова функции (при выходе из скоупа). На момент объявления `defer` значение `i` было равно 0.

### 4. Изменение Slice внутри функции

**Вопрос:** Изменится ли массив `s` в `main` после вызова `update`?

```go
func update(s []int) {
    s = append(s, 10)
}

func main() {
    s := []int{1, 2, 3}
    update(s)
    fmt.Println(s)
}
```

**Ответ:** `[1 2 3]` (не изменится).

**Почему:** Слайс — это структура, содержащая указатель на массив, длину (len) и вместимость (cap). При передаче в функцию эта структура копируется.
Функция `append` может вернуть новый слайс (с новым указателем, если capacity превышен) или тот же самый, но с увеличенным `len`. Поскольку `update` работает с копией структуры слайса, изменение `len` и потенциально указателя внутри функции не влияет на оригинальную структуру слайса в `main`.

### 5. Конкурентная запись в Map

**Вопрос:** Что произойдет при выполнении этого кода?

```go
func main() {
    m := make(map[int]int)
    go func() {
        for {
            m[1] = 1
        }
    }()
    go func() {
        for {
            fmt.Println(m[1])
        }
    }()
    select {}
}
```

**Ответ:** Паника: `fatal error: concurrent map read and map write`.

**Почему:** Стандартная `map` в Go **не является потокобезопасной**. Одновременное чтение и запись (или две записи) из разных горутин приводят к панике рантайма. Для решения нужно использовать `sync.RWMutex` или `sync.Map`.

### 6. Массивы vs Слайсы (Pass by Value)

**Вопрос:** Что выведет код?

```go
func foo(a [2]int) {
    a[0] = 100
}

func main() {
    arr := [2]int{1, 2}
    foo(arr)
    fmt.Println(arr)
}
```

**Ответ:** `[1 2]`

**Почему:** В Go массивы (array), в отличие от слайсов (slice), являются значениями. Когда вы передаете массив в функцию, он **полностью копируется**. Изменения внутри функции происходят над копией и не затрагивают оригинал.

### 7. Break в Select и For

**Вопрос:** Остановится ли цикл?

```go
func main() {
loop:
    for {
        select {
        case <-time.After(time.Second):
            fmt.Println("Time out")
            break
        }
    }
    fmt.Println("Done")
}
```

**Ответ:** Нет, будет вечный цикл.

**Почему:** Оператор `break` без метки внутри `select` прерывает только выполнение `select`, а не объемлющего цикла `for`.
Чтобы выйти из цикла, нужно использовать метку (label):
```go
break loop
```

### 8. JSON и приватные поля

**Вопрос:** Что выведет этот код?

```go
type User struct {
    name string
    Age  int
}

func main() {
    u := User{name: "Bob", Age: 30}
    b, _ := json.Marshal(u)
    fmt.Println(string(b))
}
```

**Ответ:** `{"Age":30}`

**Почему:** Пакет `encoding/json` (как и другие пакеты) не может видеть неэкспортируемые (приватные) поля структур (те, что начинаются с маленькой буквы). Поле `name` будет проигнорировано.

### 9. Операции с Nil Channel

**Вопрос:** Что произойдет в этих трех случаях с каналом, который равен `nil`?
1. Чтение из nil-канала.
2. Запись в nil-канал.
3. Закрытие (close) nil-канала.

```go
var ch chan int // nil
// 1. <-ch
// 2. ch <- 1
// 3. close(ch)
```

**Ответ:**
1. **Чтение:** Блокировка навсегда (deadlock, если нет других горутин).
2. **Запись:** Блокировка навсегда.
3. **Close:** Паника (`panic: close of nil channel`).

**Почему:** Это спецификация языка. Блокировка nil-каналов часто используется для динамического отключения кейсов в `select`.

### 10. Receiver Type (Pointer vs Value) и Интерфейсы

**Вопрос:** Скомпилируется ли этот код?

```go
type Animal interface {
    Speak()
}

type Cat struct{}

func (c *Cat) Speak() {
    fmt.Println("Meow")
}

func main() {
    var a Animal
    c := Cat{}
    a = c 
    a.Speak()
}
```

**Ответ:** Нет, ошибка компиляции.

**Почему:** Метод `Speak` определен для получателя-указателя `*Cat`.
Переменная `c` имеет тип `Cat` (значение).
Хотя Go умеет автоматически брать адрес переменной при вызове метода (`c.Speak()` сработает), при присваивании интерфейсу это не работает. Тип `Cat` не реализует интерфейс `Animal`, его реализует `*Cat`.
Нужно писать: `a = &c`.
