

# Мой ответ на собеседовании: «Расскажи про array»

---

**Array** — это встроенный тип данных в Go, представляющий собой **фиксированную по размеру** последовательность элементов одного типа. Размер массива — это **часть его типа**.

---

**По внутреннему устройству** — это просто **непрерывный блок памяти** фиксированного размера. Никаких header'ов, указателей, метаданных — чистые данные подряд в памяти:

```
[4]int в памяти (64-bit):
┌────────┬────────┬────────┬────────┐
│ int[0] │ int[1] │ int[2] │ int[3] │
│ 8 байт │ 8 байт │ 8 байт │ 8 байт │
└────────┴────────┴────────┴────────┘
Всего: 32 байта, аллоцируется на стеке (если не убегает в heap)
```

Именно поэтому array — это **value type**: при присваивании и передаче в функцию копируются **все данные целиком**.

---

**Основные моменты, которые важно знать:**

**Первое** — размер является частью типа. `[3]int` и `[4]int` — это **разные типы**, их нельзя присвоить друг другу:
```go
var a [3]int
var b [4]int
a = b  // ❌ ошибка компиляции — разные типы
```

**Второе** — при передаче в функцию **копируется весь массив**. Для большого массива это дорого, поэтому на практике либо передают указатель `*[N]T`, либо (чаще) используют slice:
```go
func process(a [1000000]int) {  // копирует ~8MB при каждом вызове!
}

func processBetter(a *[1000000]int) {  // копирует 8 байт (указатель)
}
```

**Третье** — нулевое значение массива — массив, заполненный **zero values** элементов. Не nil, не пустой — именно заполненный нулями:
```go
var a [5]int       // [0, 0, 0, 0, 0]
var s [3]string    // ["", "", ""]
var b [2]bool      // [false, false]
```

**Четвёртое** — массивы **comparable**. Их можно сравнивать через `==`, если тип элемента comparable. Это одно из преимуществ над slice:
```go
a := [3]int{1, 2, 3}
b := [3]int{1, 2, 3}
fmt.Println(a == b)  // true

// Именно поэтому массив может быть ключом map:
m := map[[2]int]string{
    {0, 0}: "origin",
}
```

**Пятое** — размер может быть вычислен компилятором через `...`:
```go
a := [...]int{1, 2, 3, 4, 5}  // тип [5]int, компилятор считает сам
```

**Шестое** — массив — это **основа для slice**. Любой slice под капотом ссылается на underlying array. Можно явно сделать срез:
```go
arr := [5]int{10, 20, 30, 40, 50}
s := arr[1:4]   // slice [20, 30, 40], указывает на arr
s[0] = 99       // arr становится [10, 99, 30, 40, 50]
```

**Седьмое** — массивы хорошо ложатся на **стек**. Компилятор может аллоцировать массив на стеке (escape analysis), что значительно быстрее heap-аллокации. Это делает маленькие массивы отличным выбором для performance-critical кода:
```go
// Часто используется в стандартной библиотеке:
var buf [64]byte  // на стеке, zero allocations
```

**Восьмое** — `len` и `cap` массива — это **одно и то же значение**, и оно известно на этапе компиляции. `len([5]int{})` — это константа:
```go
var a [5]int
len(a)  // 5 — compile-time constant
cap(a)  // 5 — то же самое
```

---

**Практическое применение.** В реальном Go-коде массивы используются редко напрямую, но есть конкретные случаи:
- **Ключи map** — `map[[16]byte]Value` (например, UUID, хеши)
- **Фиксированные буферы** — `[512]byte` для IO без аллокаций
- **Криптография/хеши** — `sha256.Sum256()` возвращает `[32]byte`
- **Внутренности стандартной библиотеки** — underlying storage для slice
