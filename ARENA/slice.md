# Мой ответ на собеседовании: «Расскажи про slice»

---

**Slice** — это встроенный тип данных в Go, представляющий собой динамическую последовательность элементов одного типа. По сути — обёртка над массивом с автоматическим управлением размером.

---

**По внутреннему устройству** — это структура из трёх полей, называемая **slice header** (`reflect.SliceHeader`):

```go
type SliceHeader struct {
    Data uintptr  // указатель на underlying array
    Len  int      // текущая длина
    Cap  int      // ёмкость (от Data до конца массива)
}
```

Именно поэтому slice ведёт себя как ссылочный тип: при передаче в функцию копируется header (24 байта), а не данные. Изменения элементов видны снаружи, но изменение длины — нет (это изменение локальной копии header).

---

**Основные моменты, которые важно знать:**

**Первое** — нулевое значение slice это `nil`. У `nil` slice `len` и `cap` равны нулю, но `append` к нему работает нормально — это идиоматично. Также `len(nil) == 0` — не паникует.

**Второе** — slice можно создать тремя способами:
```go
s := []int{1, 2, 3}           // литерал
s := make([]int, len, cap)    // make с длиной и опциональной ёмкостью  
s := array[start:end]         // срез от массива или другого slice
```

**Третье** — несколько slice могут **разделять один underlying array**. Это мощно, но опасно:
```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]        // b = [2, 3], но указывает на тот же массив
b[0] = 99          // a становится [1, 99, 3, 4, 5]
```

**Четвёртое** — **append** возвращает новый slice header. Если `cap` достаточно — дописывает в существующий массив. Если нет — аллоцирует новый массив, копирует данные, возвращает slice с новым указателем. Поэтому всегда `s = append(s, ...)`.

**Пятое** — **стратегия роста**: до 256 элементов — удвоение; после — рост примерно на 25% (формула `newcap += (newcap + 3*threshold) >> 2`). Плюс выравнивание под memory size classes. Поэтому если знаешь размер заранее — лучше указать `cap` в `make`, чтобы избежать реаллокаций.

**Шестое** — **full slice expression** `a[low:high:max]` позволяет ограничить capacity:
```go
b := a[1:3:3]  // len=2, cap=2 (а не до конца массива)
```
Это защита от случайного перезаписывания данных при append.

**Седьмое** — нельзя сравнивать slice через `==` (кроме сравнения с `nil`). Для сравнения содержимого — `slices.Equal()` из стандартной библиотеки (Go 1.21+) или ручной цикл.

**Восьмое** — частая ошибка: **утечка памяти** при срезе большого slice:
```go
big := make([]byte, 1<<20)       // 1MB
small := big[:10]                // small держит ссылку на весь 1MB
// Правильно:
small := append([]byte{}, big[:10]...)  // копия
```

---

**Ну и copy** — встроенная функция `copy(dst, src)` копирует `min(len(dst), len(src))` элементов. Возвращает количество скопированных.
